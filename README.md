# DisplaySwitch — 无畏契约「真实拉伸」/「日常」一键切换

把「禁用监视器 → 改自定义分辨率 1280×882 → 打完再改回 2560×1600」这一串手工操作，压缩成**一次双击**。

纯 C++ / 纯 Win32 API，**零第三方依赖、免安装**，不碰注册表以外的任何东西（改分辨率本身会写注册表，这是 Windows 的正常机制）。

> **关于本仓库**：这是个自用的个人小工具，配置和实测数据都基于我自己的笔记本（NVIDIA 独显直连 + 单块 2.5K 240Hz 内置屏）。
> 第 0 节的实测值**仅供参考**，换机器要按第 3 节重新建基准、按第 6 节调配置。
> 想直接用的话，建议先看第 0、3 节了解原理，再照着第 5 节跑一遍。

现在有两个前端，共用同一套核心代码：

| 程序 | 形态 | 适合 |
|---|---|---|
| **`DisplaySwitch.exe`** | 图形界面（Win32 原生窗口 + 托盘 + 全局热键） | 日常使用、想看状态、想改设置 |
| **`DisplaySwitchCLI.exe`** | 控制台命令行 | 做快捷方式、脚本调用、应急排查 |

## 0. 你这台机器的实测情况

程序里的探针读出来的真实参数，它们决定了整套设计：

| 项目 | 实测值 |
|---|---|
| 显卡 | NVIDIA，单适配器 `PCI\VEN_10DE&DEV_28A0`（**独显直连 MUX**，无核显混合） |
| 内置屏 | `TL160ADMP11-0`，接口 **eDP**（`DISPLAYPORT_EMBEDDED`），2560×1600 @ 240Hz，`\\.\DISPLAY1` |
| 「监视器」设备 | `DISPLAY\TMX1601\5&37D6328&1&UID4357`，硬件 ID `MONITOR\TMX1601`，**本来就是禁用状态**（问题码 22 = `CM_PROB_DISABLED`） |
| 自定义分辨率 | **`1280×882` 已存在于模式表中（可选 240Hz）** —— 你已经建好了 |
| CCD 路径总数 | 24 条，其中只有 1 条 ACTIVE（其余都是没插线的 DP/DVI/HDMI 接口） |
| 管理员权限 | **改分辨率不需要**；只有「禁用/启用监视器设备」才需要 |

### 一个重要的机制澄清

「禁用笔记本**内置显示器**」和「禁用**监视器**设备」在 Windows 里是**完全不同的两件事**：

- 禁用**显示器/显卡输出**（`Win+P` → 仅电脑屏幕、CCD 拓扑）→ 这是**关掉画面输出**。在只有一块屏的机器上做这个，会**直接黑屏**。
- 禁用**「监视器」设备**（设备管理器 → 监视器 → 通用即插即用监视器）→ 画面**照常显示**，只是 Windows 不再读这块屏的 EDID。

**EDID 里写死了面板「官方支持」的时序，显卡据此限制可选分辨率列表。** 把监视器设备禁用掉，系统就不再受 EDID 约束，NVIDIA 控制面板里创建的自定义分辨率才能真正被应用 —— 这才是那一步手动操作的真实作用。

你这台机器的现状正好印证：**监视器设备一直是禁用的，屏幕照样正常跑 2560×1600**。

> 也正因为如此，本程序默认 `daily_enable_monitor=0`：回日常时**按存档还原**监视器设备状态（保持禁用），而不是去强行启用它。否则每次回日常都会因为需要管理员权限而失败。
> 如果你的机器情况不同（监视器设备平时是启用的），把这一项改成 `1` 即可。

## 3. 首次使用（三步）

1. **建基准**：先确保画面是日常状态（2560×1600），双击 `DisplaySwitchCLI.exe`，或者双击 `run-check.bat` 确认一下，然后在图形界面里点 **「存为日常基准」**。
   > 这一步把当前的分辨率/拓扑/监视器状态存进 `daily.ccd` 等文件，以后「回日常」就是照着它还原。
2. **建快捷方式**：双击 `make-desktop-shortcut.bat`，桌面会出现两个快捷方式：
   - `DisplaySwitch GUI` → 打开图形界面
   - `DisplaySwitch Toggle` → 一键切换（无窗口，双击即切）
   建好后可以按 F2 改成中文名。
3. **全局热键已经配好了**：`display.cfg` 里默认写的是 `hotkey=Ctrl+Alt+S`。
   想换组合就在图形界面的「全局热键」框里改，再点「保存设置到 display.cfg」，然后重启程序。
   之后**在游戏里**按 `Ctrl+Alt+S` 就能直接切换。不想用就把这一行留空。

## 6. 配置文件 `display.cfg`

记事本直接改，或者用图形界面改完点「保存设置」。

```ini
stretch_width=1280          # 拉伸分辨率宽
stretch_height=882          # 拉伸分辨率高
stretch_refresh=0           # 0 = 自动取该分辨率下最高刷新率
stretch_target=internal     # internal=笔记本内置屏 / external=外接屏 / auto=自动
stretch_disable_monitor=1   # 拉伸时禁用「监视器」设备（解除 EDID 限制）
daily_enable_monitor=0      # 回日常时: 1=强行启用监视器设备 / 0=按存档还原（推荐 0）
keep_external_only=1        # 拉伸时是否只保留一块活动的屏
settle_ms=1500              # 每次改完等待稳定的毫秒数
log=1                       # 是否写 DisplaySwitch.log
auto_elevate=1              # 需要时自动弹 UAC 提权
open_nvcp_on_missing=1      # 找不到自定义分辨率时自动打开 NVCP
internal_match=             # 手工指定内置屏关键字（留空=按接口类型判断）
monitor_match=              # 手工指定监视器设备关键字（留空=自动匹配）
hotkey=Ctrl+Alt+S           # 全局热键（仅图形版）
```

## 7. 切换流程

### 切到【真实拉伸】
1. 读当前显示状态，确认目标屏（内置屏）是活动的。
2. 找到目标屏对应的**监视器**设备节点。
   - 已经是禁用状态 → 跳过（本机就是这种情况，所以**不需要管理员权限**）。
   - 还是启用状态 → 调用 `CM_Disable_DevNode` 禁用它（**这一步需要管理员**，程序会自动弹 UAC 提权重跑）。
3. 等 1.5 秒让系统重新枚举显示模式（EDID 消失后模式表会刷新）。
4. 在目标屏上应用 `1280×882`（`ChangeDisplaySettingsExW`）。
5. 校验：重新读取，确认分辨率真的是 1280×882。
   - 成功 → 记录回滚点，退出码 0。
   - 失败 → 按回滚点还原（三级降级，见下）。

### 切回【日常】
1. 读当前状态，按 `daily.mon` 存档还原监视器设备状态（本机保持禁用，**不需要管理员**）。
2. 按 `daily.ccd` 存档精确还原显示拓扑 + 分辨率。
3. 校验；不一致就走降级方案（切扩展模式 → 逐屏还原分辨率）。

### 三级降级回滚
任何一步失败都会按顺序尝试：

1. **严格还原**：用回滚快照调 `SetDisplayConfig(SDC_USE_SUPPLIED_DISPLAY_CONFIG)`。
2. **放宽还原**：加上 `SDC_ALLOW_CHANGES | SDC_PATH_PERSIST_IF_REQUIRED | SDC_ALLOW_PATH_ORDER_CHANGES` 重试。
3. **拓扑兜底**：切到「扩展模式」把内置屏拉回来，再逐屏设分辨率。

存档文件用「二进制快照 + `FNV-1a` 哈希校验」，文件损坏会被发现并拒用，不会拿着坏数据乱改你的显示配置。

## 9. 常见问题

**Q：点了切换没反应？**
看 `DisplaySwitch.log` 最后几行，或者双击 `run-check.bat`。退出码含义见第 5 节。

**Q：弹了 UAC 窗口？**
说明这一步需要管理员权限（正在禁用/启用监视器设备）。**允许它**，程序会在提权后的新进程里把操作做完。
你这台机器的监视器设备本来就是禁用的，所以正常使用时**不应该**弹 UAC。如果弹了，检查 `display.cfg` 里 `daily_enable_monitor` 是不是被改成 `1` 了。

**Q：NVIDIA 控制面板里找不到 1280×882？**
双击 `run-stretch.bat` 时会提示，图形界面会给出提示，也可以点「打开 NVIDIA 控制面板」→ 显示 → 更改分辨率 → 自定义 → 新建 `1280×882`。
建的时候注意：**先让监视器设备处于禁用状态**，否则 NVCP 可能不让保存。

**Q：切换后画面比例不对？**
NVIDIA 控制面板 → 调整桌面尺寸和位置 → 缩放模式选 **「全屏」**，并勾选「覆盖游戏和程序设置的缩放模式」。

**Q：怎么彻底恢复成没装过这个程序的样子？**
1. `DisplaySwitchCLI.exe daily` 回到日常；
2. 设备管理器 → 监视器 → 右键「通用即插即用监视器」→ 启用设备（如果你想让它是启用状态）；
3. 删掉 `D:\DisplaySwitch` 整个文件夹。

**Q：快捷键被别的程序占用了？**
换个组合，比如 `Ctrl+Alt+F9`。

## 10. 重新编译

双击 `build.bat`。它会依次编译资源（清单 + 图标）和两个前端。

手动编译（在 `D:\DisplaySwitch` 下）：

```bash
# 资源
Y:/msys64/ucrt64/bin/windres.exe src/gui.rc -O coff -o build/gui.res

# 图形界面版（注意 -mwindows 和 -municode 都要有）
Y:/msys64/ucrt64/bin/g++.exe -std=c++17 -O2 -DUNICODE -D_UNICODE \
    -static -s -mwindows -municode \
    src/core.cpp src/main_gui.cpp build/gui.res -o DisplaySwitch.exe \
    -luser32 -lgdi32 -lshell32 -lsetupapi -lcfgmgr32 -lcomctl32

# 控制台版
Y:/msys64/ucrt64/bin/g++.exe -std=c++17 -O2 -DUNICODE -D_UNICODE \
    -static -s \
    src/core.cpp src/main_cli.cpp -o DisplaySwitchCLI.exe \
    -luser32 -lgdi32 -lshell32 -lsetupapi -lcfgmgr32
```

> ⚠️ 图形版必须同时加 `-mwindows` 和 `-municode`。只用 `-mwindows` 会报
> `undefined reference to WinMain`（因为入口是 `wWinMain`），而且 MinGW 有时
> 不打印具体原因，只给一行 `collect2.exe: error: ld returned 1 exit status`，很难查。

图标缺失时用 `python tools/make_icon.py` 重新生成（纯标准库，不需要 Pillow）。

> ⚠️ 所有 `.bat` 脚本都**必须保持纯 ASCII**（连 `rem` 注释都不能有中文）。
> `cmd.exe` 是按系统 OEM 代码页（中文系统是 GBK）读 `.bat` 的，UTF-8 中文会被解析成乱码，
> 直接报 `'岄潰' 不是内部或外部命令`，而且会**打断 `^` 行续接**，让整段命令散架。
> 中文说明写在 `README.md` 里就好。

## 11. 技术要点

- **显示拓扑 / 分辨率**：`QueryDisplayConfig` / `SetDisplayConfig` / `ChangeDisplaySettingsExW`
- **监视器设备开关**：`SetupDiGetClassDevs(GUID_DEVCLASS_MONITOR)` + `CM_Disable_DevNode` / `CM_Enable_DevNode`
- **内置屏识别**：现代笔记本的内屏报 `DISPLAYPORT_EMBEDDED`(11) 而不是 `INTERNAL`，所以判断要覆盖 INTERNAL / LVDS / DISPLAYPORT_EMBEDDED / UDI_EMBEDDED 四种
- **提权**：`ShellExecuteExW("runas")`，子进程带 `--elevated` 标记避免无限递归；父进程等待子进程退出并回传退出码
- **图形界面**：全部手写 Win32 + `comctl32`，`-mwindows`，无 MFC/Qt。操作跑在工作线程里，日志通过 `PostMessage` 回主线程，界面不会卡死
